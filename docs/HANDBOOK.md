## 5. Code management (GitHub)

**One repo, one folder per subsystem** (see README).

**Branches**
- `main` is always working. Nobody pushes to it directly.
- Work on a branch named after the ticket: `AL-12-login-screen`.

**Everyday flow**
```bash
git checkout main && git pull
git checkout -b AL-12-login-screen
# ...work...
git add .
git commit -m "AL-12: add login screen"
git push -u origin AL-12-login-screen
# then open a Pull Request on GitHub
```

**Pull request rules**
- Small PRs (under ~300 changed lines where possible).
- Fill in the PR template.
- CI must be green.
- One teammate approves. Anything in `firebase/`, `blockchain/`, `compose.yaml` or `.github/` needs the lead.
- Squash and merge, then delete the branch.
- Pull `main` into your branch often to avoid big merge conflicts.

**Protect `main` (lead):** repo Settings > Branches > Add rule for `main`:
require a pull request, require 1 approval, require the `CI` checks to pass.
(On a free private repo this option may be locked. Fix: GitHub Student
Developer Pack gives free Pro, or make the repo public, or just agree the rule
as a team.)

**Secrets**
- Never commit: `.env`, `secrets/`, `google-services.json`, private keys.
- `.gitignore` already covers them. If a key leaks, tell the lead and **rotate it** (deleting the commit is not enough).
- Shared by direct message or the shared password manager only.
- The Anvil test accounts and their keys are public knowledge and are fine to use locally, but never on a real network.

**Definition of done** (a Jira ticket only moves to Done when all of these are true)
- Code is merged to `main` via an approved PR with green CI.
- Tests exist for the new behaviour (or the PR explains why not).
- Docs are updated if setup, API or data model changed.
- The Jira ticket is moved and linked to the PR.

**Contributions:** commit under your own GitHub account, in small commits, with the ticket ID in the message. The Git history is the record of who did what.

## 6. Development environment

**Install**

| Who | Install |
|-----|---------|
| Everyone | Git, Docker Desktop, VS Code |
| Mobile | Android Studio |
| Web | Node 22 LTS |
| AI | Python 3.12 + Jupyter (for training the valuation model) |
| Lead | Node 22 LTS, Firebase CLI, Foundry (`forge`, `anvil`, `cast`) |

**Windows users:** run shell scripts from Git Bash or WSL.

**First-time setup**
```bash
git clone <repo-url> && cd al-agentic-lender
cp .env.example .env                 # ask lead for keys by DM
# put firebase-service-account.json in secrets/
docker compose up -d --build
docker compose logs -f ollama-pull   # wait for the model download (first time only)
./scripts/smoke-test.sh              # every line should say OK
```

**Daily**
```bash
git pull
docker compose up -d --build                 # everything
docker compose up -d --build ai-engine       # just your part after a code change
docker compose logs -f ai-engine             # see errors
docker compose down                          # stop
```
After editing `.env`, run `docker compose up -d` again so containers pick up the change. If you add a new variable, add it to `.env.example` too (blank value).

**Run only what you need:** mobile dev needs just `docker compose up ai-engine`
(this starts Ollama and the chain too). Contract dev: `docker compose up blockchain deployer`.

**Blockchain:** the `blockchain` service runs Anvil at `http://localhost:8545` (chain ID 31337). The `deployer` service runs the Foundry deploy script and writes the deployed contract addresses to a shared config file that the web app and Python service read, so they always stay in sync.

**Firebase**
- One shared Firebase project (Auth + Firestore). All four are Editors on it.
- **Day-to-day work uses the emulators**, so our test data doesn't collide in the shared project:
  `cd firebase && firebase emulators:start` (UI at http://localhost:4000).
  Use the real project only for integration checks and the demo.
- Web keys go in `web/.env` as `VITE_FIREBASE_*` (gitignored).
- Android: `google-services.json` goes in `mobile/app/` (gitignored).

**Android** reaches the API at `http://10.0.2.2:8000`.

## 7. Testing

| Part | Tool | Run |
|------|------|-----|
| API / ML / agents | pytest + FastAPI `TestClient` (mock the LLM calls) | `cd ai-engine && pytest` |
| Web | Vitest + React Testing Library (`"test": "vitest run"`) | `cd web && npm test` |
| Mobile | JUnit unit tests | `cd mobile && ./gradlew testDebugUnitTest` |
| Firestore rules | Firebase emulator + `@firebase/rules-unit-testing` | lead |
| Whole stack | smoke test | `./scripts/smoke-test.sh` |

`forge test` runs contract tests in its own in-memory EVM, so you don't need Anvil running for unit tests. Use Anvil (via Docker Compose) for end-to-end checks with the API and web app.
